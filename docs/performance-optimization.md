# Cat Quest Windows Performance Optimization Report

[English](performance-optimization.md) | [简体中文](performance-optimization.zh-CN.md)

November 2, 2026. The 15 findings below follow the numbering of the original performance audit. Dashboard texture memory fell from **3,256 MiB to 619 MiB**. With 144 tasks, the longest frame when switching to Todo fell from **317 ms to 20 ms**. During an active Focus session, median managed memory allocation fell from **122 KiB to 0.20 KiB per frame**.

On the same platform, the uncompressed Windows Development Build directory shrank from **3,330 MiB to 985 MiB**, including the Unity runtime and development build files.

## Measurement conditions

The main comparison used a Unity 6000.3.10f1 Windows Development Player on the same Windows 11 laptop with an Intel Core i7-14650HX and an NVIDIA GeForce RTX 4060 Laptop GPU. The main window ran at 1920×1080 on Direct3D 12 (DX12), using the Very Low quality preset and an isolated save with 144 synthetic tasks. Separate runs covered 24 tasks at 1280×720 and the desktop Companion running in its own Direct3D 11 (DX11) process. The tests used the saved version of the scene.

In the table, **peak frame time** is the longest interval between frames in the first 12 frames after an action starts. **Peak allocation** is the most managed memory allocated in any one frame in that window. Steady-state measurements exclude the first 25 frames. Baseline timings come from the equivalent route in the original audit. A separate pre-optimization Player provided the visual baseline. The updated main window is capped at 60 FPS, so its 16.67 ms frame interval includes any time spent waiting and cannot establish how long the GPU or main thread worked. Each set of figures represents one run on this machine. Absolute timings vary between runs.

## Findings, changes and results

| # | Performance issue | What changed | Profiler measurements and verification |
|---|---|---|---|
| 1 | Individual RGBA32 animation textures for Ninja Cat and Sensei stayed in memory. | Project-owned Sprite Atlases group frames by character, action and filter mode. The Windows build uses BC3/DXT5 compression with alpha. Unity maps each original sprite to its packed texture at runtime, preserving the source images, pivots, GUIDs and animation clips. | On the Dashboard, the character pack went from **515 loaded textures using 2,058 MiB** to **30 loaded atlas pages using 226 MiB**. |
| 2 | Focus copied the entire save every frame to count spectator fish. | Focus caches the fish count using the whole-minute count, date and committed data version. The reward preview reads only the current day's record. Callers that need to modify data still receive independent copies. Fish movement and Focus reward settlement retain their existing logic. | With 144 tasks and Focus running, median allocation fell from **121.98 to 0.20 KiB/frame**. A separate comparison with both runs capped at 60 FPS measured **118.45 to 0.20 KiB/frame**. |
| 3 | Long task lists and searches repeatedly recreated every control. | The list reuses rows, headings and tags in the visible area and a buffer on either side. Placeholders preserve the scroll range. Short lists display all rows. Each refresh shares one task-query snapshot, and navigation no longer triggers a second refresh. Recycled rows retain their checkbox and tag references and bind actions to the newly displayed task. | First opening Tasks fell from **421 to 74 ms**, switching to Todo from **317 to 20 ms**, and switching to Tags from **325 to 17 ms**. Entering a first search character that still matched many tasks fell from **206 to 17 ms**. Peak allocation on the Todo switch fell from **37.1 to 0.90 MiB**. |
| 4 | The hidden Tasks page still handled save events. | Tasks unsubscribes when the user leaves. On return, it displays the current tab, date and data. Draft submission and the existing page-exit behavior are preserved. | On the standard route, after opening Tasks, the peak when starting Focus fell from **223 to 65 ms**. End Early fell from **191 to 44 ms**. Both measurements include the effects of findings 2 and 11. |
| 5 | The main app polled files and wrote heartbeats even with the Companion closed. | The main app skips the communication loop when it has no child process. It publishes the initial state before launch and resumes heartbeats, identity checks and duplicate detection once connected. It recalculates the equipment aura only when the data version changes. The window toggle refreshes only when its state changes. | On the Dashboard with 144 tasks, a 60 FPS cap and the Companion closed, the peak frame time in the comparison window fell from **41 to 17 ms**. The main Player also launched a real Companion process. File I/O continues while the two processes are connected. |
| 6 | Unvisited stages, training backgrounds and Acorn animation frames occupied memory. | Background atlases group assets by environment pack, filter mode and mipmap setting. Each of the three Boss stages and the Focus stage has its own resource entry pointing to the original prefab and GUID. Focus loads its art asynchronously on demand and detaches the callback if the user leaves during loading. The timer runs independently of the artwork. | On the Dashboard, the environment packs used about **895 MiB** before the change. Their loaded atlas pages used about **210 MiB** afterward. The opening scene loaded **0 Acorn atlas pages**. Synchronous work on the first visit to Focus fell from **26.5 to 8.6 ms**. Steady-state Focus texture memory was about **740 MiB** afterward. |
| 7 | Returning to the Dashboard rebuilt the entire task preview. | The Dashboard reuses visible rows in the same way as Tasks. It retains the existing groups, access to every task and click actions. Each update uses a single query snapshot. | Returning to the Dashboard fell from **308 to 17 ms**. Peak allocation fell from **32.2 to 0.83 MiB**. |
| 8 | Selecting a date queried the whole month again and rebuilt the date drawer. | The calendar invalidates its monthly data when the month, current date, data version, search or filters change. Selecting a different day reuses the monthly results. The date drawer also reuses visible rows. | Opening the date drawer fell from **92 to 36 ms**, with peak allocation down from **10.3 to 3.3 MiB**. Opening the monthly calendar for the first time still calculates and binds all 42 days. |
| 9 | The idle main window rendered at hundreds of frames per second. | On Windows, the main window targets 60 FPS in the foreground and 30 FPS when it loses focus. The separate Companion retains its 30 FPS target. Focus timing continues to use a monotonic clock. | The median steady-state frame interval was about **16.67 ms** on the Dashboard and **33.33 ms** in the 420×300 Companion. Power draw and battery life were outside the measurements. |
| 10 | Scene previews allocated render textures at fixed high resolutions. | Previews size their render textures to the displayed `RawImage` and Canvas scale, preserving aspect ratios and size limits. Focus now releases its render texture on page exit. Boss continues to release its texture on exit, and the character preview keeps its texture for reuse. | Total render texture memory fell from **72.5 to 48.6 MiB** on the Dashboard, **134.9 to 111.5 MiB** on the Boss page and **12.4 to 3.0 MiB** in the Companion. Each figure is the total for the measured process. |
| 11 | Reading a balance, tag, daily reward record or receipt also read the full `PlayerData` object. | Callers can query individual values, tags, daily reward records and Focus or Boss receipts. Task views share a read snapshot. Writes retain their copy, atomic replacement, backup and retry behavior. Regression checks cover on-demand reads of legacy reward records, callers modifying copies, failed writes, successful replacements and crossing into a new day. | Completing a task fell from **239 to 63 ms**. Peak allocation fell from **25.3 to 3.0 MiB**. Synchronous saves and some larger queries still take time. |
| 12 | Appending one chat reply rebuilt the entire conversation. | Appending a message creates only its bubble. Changes to draft content or status rebind only that card. Restoring a long conversation creates up to 8 messages per batch. Clearing or replacing the conversation removes old rows. Draft confirmation and permissions retain their existing behavior. | With 80 local messages, the initial display peak fell from **71 to 17 ms**. Appending message 81 also fell from **71 to 17 ms**, with peak allocation down from **7.4 MiB to 55 KiB**. The lower initial peak comes from spreading the full conversation across several frames. |
| 13 | Boss entry, battle settlement and equipment refreshes triggered unrelated work. | The Boss page reads only the stage, mastery and current battle receipt it needs. The inventory reuses item controls by equipment ID and reuses empty slots, preserving bindings and upgrade feedback. These operations also benefit from findings 3, 4 and 11. | Boss 1 entry fell from **166 to 35 ms**, and Boss 3 entry from **203 to 57 ms**. Viewing equipment details and upgrading fell from **78 to 51 ms** for the combined action. Selecting a Boss stage for the first time still incurs its asset-loading cost. |
| 14 | Opening a 50-row leaderboard created every row in one frame. | The leaderboard fills up to 8 rows initially, then up to 6 new rows per frame. Switching categories reuses existing rows. New results replace any data still waiting to be displayed. | Opening a local 50-row leaderboard fell from **45 to 21 ms**, with peak allocation down from **3.1 to 0.77 MiB**. This test used local data and did not contact the live leaderboard backend. |
| 15 | Reward labels and static UI repeatedly formatted the same values, and rendering required many draw calls. | Balance and experience labels format text only when their displayed values change. Shared labels stay in sync during the coin-flight animation. Sprite atlases and reuse of visible list rows reduced the measured draw calls. | Dashboard draw calls fell from **190 to 160** and idle Boss draw calls from **248 to 223**. Median steady-state Dashboard allocation fell from **0.393 to 0.203 KiB/frame**. |

## Windows shutdown stability

In one run, the DX12 main Player completed all 41 sampled states and wrote its data, then exited with `0xC0000005`. Windows named `D3D12Core.dll` as the faulting module. The original audit had also recorded a shutdown exception in that module. Several other DX12 runs exited normally. At the time of the audit, the available evidence identified the native module but did not establish the specific trigger in Unity, the driver or a game asset.

On November 2, the same build that had crashed was run with DX11 forced. It returned exit code 0 on the full 144-task route, including the real desktop Companion, and on two exits from the story scene. [Windows fault event](../Library/PerformanceFix-20261102/windows-crashes.txt) · [Full DX11 route](../Library/PerformanceFix-20261102/dx11Route/exit.txt) · [First story exit](../Library/PerformanceFix-20261102/dx11Exit2/exit.txt) · [Second story exit](../Library/PerformanceFix-20261102/dx11Exit3/exit.txt)

On November 3, following that comparison and the project owner's approval, the Windows Player switched from automatic graphics API selection to an explicit order of Direct3D 11 followed by Direct3D 12. A normal launch uses DX11. The desktop Companion continues to use DX11 in its own process. On a machine that supports DX12, run the following command from the new build directory to select it. [Settings read back from Unity](../Library/WindowsGraphics-20261103-0614/settings.txt) · [Windows Development Build result](../Library/WindowsGraphics-20261103-0614/build.txt)

```powershell
.\CatQuest.exe -force-d3d12
```

The new build ran four times on the same Windows 11 machine with isolated saves. Unity's device log reported Direct3D 11 for all three default launches and Direct3D 12 for the explicitly requested launch. Each run started and settled a Focus session, and all four main processes exited with code 0. The first default run also opened the real desktop Companion. Closing it left the main timer running, and the Companion process exited with code 0. These runs verified backend selection and shutdown. The performance figures in the table come from the November 2 measurements of the DX12 main window. ## Outstanding equipment layout check

The inventory Play Mode run completed the checks for claiming, equipping and unequipping items, filtering the nine items, upgrading, Auto Select, balances, repeated actions and persistence. The full layout check then stopped on the Dashboard at 1920×1080 with the sidebar collapsed. With all three slots equipped, the lower edge of each slot's rendered mesh overlapped the boundary of the Power badge. The measured vertical gap was **−1.86 px** for each slot against a requirement of **more than 4 px**. Running the pre- and post-optimization Players with the same isolated, fully equipped save produced identical control coordinates, rendered gaps and save file SHA-256 hashes. The layout discrepancy remains open for a separate UI change. The full equipment Play Mode suite was recorded as incomplete. [Failed assertion](../Library/PerformanceFix-20261102/check-inventory.txt) · [Baseline geometry](../Library/PerformanceFix-20261102/fullgear-before/geometry.tsv) · [Post-optimization geometry](../Library/PerformanceFix-20261102/fullgear-after/geometry.tsv)

Performance sampling used development builds with temporary probes. The delivered build removed the probes, explicitly saved importer settings for a group of textures already using DXT5 at runtime, and cleaned up task tag counts and a legacy input marker. The before-and-after figures come from instrumented runs with complete action logs. The temporary generators, diagnostic scripts and their `.meta` files were removed from `Assets/`. [Delivered binary verification](../Library/PerformanceFix-20261102/delivered-binary.txt)

The paths changed for the optimization passed `git diff --check`. The repository-wide check also reported 5 lines with trailing whitespace in the CharacterHome scene changes the project owner had saved before the work began. Those scene edits were preserved.

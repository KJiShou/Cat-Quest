The capture used the already-open Unity **6000.3.10f1** instance and `Assets/Scenes/CharacterHome.unity`. Tutorial dismissal, tasks and equipment were seeded only in the disposable demo save. No real player save, task history or online account was used. Page selection and Settings opening were driven programmatically for documentation. These images do not establish pointer/keyboard behavior, animation quality or Windows Companion behavior.

Raw evidence and the restoration report remain in ignored `Library/ReadmeCapture-20261031/`. The temporary capture script was removed afterward. The normal save environment, Play Mode start scene, Game View selection/custom size count, pause/time scale and scene state were restored. No authored prefab/scene was saved by the capture.

An initial attempt with the existing Settings Play verifier stopped because the new-user tutorial blocked `Button_Setting`. Its report is under `Library/SettingsVerification/20261031-140121-5baea84d19784cca8001341faf5b8f15/`. The documentation capture does **not** override or turn that failed interaction check into a pass.

Only these curated documentation copies are tracked. Keep raw screenshots, test saves and reports under ignored `Library/` or `Temp/`. Screenshots retain the rights of the original project and third-party artwork. See [third-party notices](../../THIRD_PARTY_NOTICES.md).

## Later UI changes

These captures predate the Tasks calendar, expanded Todo/Dashboard date groups, default-task-tab selector and the November 1 compact-button palette/border update. They remain historical illustrations, not evidence of the current UI. Current verification captures stay under ignored `Library/TaskCalendarVerification/` and `Library/ButtonSurfaceVerification/`; they are not published README images.

# Equipment

Source: Cat Quest.pdf sections 4.4.8, 4.5.4, Tables 4.6-4.8, 4.5.5 and 4.6.4 (PDF pages 58, 62-67, 75).

- Three deterministic Boss sets, each with Weapon (ATK), Armour (DEF), Head Accessory (ASPD).
- Level 1 on acquisition. Weapon/body bonus = 2T + 0.5(E - 1); head bonus = 0.05T + 0.01(E - 1).
- Upgrade E to E+1 costs 10+5E Fish, capped by Cat Level. All changes persist atomically; upgrade request receipts make retries idempotent.
- Two-piece bonus is 5T percent of level-derived maximum HP, rounded half upward. Three pieces retain this and add T ATK, T DEF and 0.02T ASPD. Mixed sets do not combine.
- Final stats drive battle damage and actual attack intervals; confirmed attempts snapshot both final stats and equipped items/levels. Equipment changes are blocked during running battles.
- Normal Boss victories 5/10/15 unlock the fixed Weapon/Body/Head rewards respectively. Claims grant no Fish; later wins after the full set grant the existing post-set rewards.
- Schema 5 preserves task/focus/currency/Boss progress and outstanding mastery claims, adds inventory/equipped IDs/upgrade receipts and permanent equipment unlock.
- Compatibility with the existing two independent Daily Reward cards: claiming either card unlocks equipment permanently. This implements first-Daily-Reward access without changing the established reward system.
- Cat Home shows the forest/cat preview, three slots below it (weapon, armour, helmet), coloured HP/ATK/DEF/ASPD bars with white values, and a square inventory grid. Four filters: All, Helmet, Weapon, Equipment. No capacity or selling UI. Stage armour bars open claim dialogs directly on Boss; there are no claims in Cat Home. Dashboard slots show equipped gear and link to item management.
- Equipment icons use existing GUI Pro assets. Items change combat stats; no new cat skins or crafting/enhancement tree are introduced.

Equipment bindings are already serialized in Assets/Prefabs/Canvas.prefab. The one-off page setup tool has been retired; update the affected component or prefab section without rebuilding the page.

The scene binds LiveCat to the existing preview camera and character. Settings is also a pre-placed, initially inactive nested prefab in Canvas; SettingsLauncher opens its serialized instance.

This migration preserves existing visual styling and runtime inventory item templates. Task filter/confirmation dialogs and the Focus application-exit confirmation still have runtime construction paths; they have not been migrated by this change.

Visual grade: Cyclope blue, Orc purple, Demon yellow. Backpack items, worn slots and claim choices use SimpleCasual rounded UI backgrounds with tier colours. Animated EquipmentGradeEffect borders are no longer generated. Upgrade hover feedback and battle weapon effects remain separate and unchanged.

Auto Select evaluates every owned loadout including set bonuses, retains the existing loadout on equal Power, then commits the best loadout atomically on click without confirmation. It respects the unlock and active battle gates. The four stat rows show authoritative final values and a separate +gear amount, including equipment and set bonuses. Zero bonuses use muted text. They have no fill or implied maximum; speed and its bonus are shown per second.

Clicking the backdrop closes the detail without activating the underlying page; clicks inside the card and drags do not dismiss it. Equip/unequip execute directly and show their result in the detail panel. Upgrade executes directly from the Fish button, with failures shown in the detail status. The mastery chests claim directly; the separate unowned-item detail still retains its Claim confirmation; Auto Select directly equips the strongest owned loadout; service settlement remains authoritative. The project Fredoka font is retained. The two Canvas EquipmentPageUI components reference this prefab; the Boss mastery choice panel remains separate.

Both show final equipped HP/ATK/DEF/ASPD plus Total Power from CombatStats.Power, including set bonuses. Dashboard slot backgrounds now use the same tier tints as Cat Home. Equipment detail, mastery choices and confirmation overlays cover the root Canvas and block header/sidebar input while retaining page lifecycle ownership. The Cat Home inventory surface uses the editable Assets/Prefabs/EquipmentInventory.prefab adapted from Light/Equipment.prefab Right_Panel: separate filter strip, six-column/four-row item grid with level badges, and Auto Select. Sale, capacity counters, Inventory/Equipment headings and the blue saved message are omitted. Empty/locked guidance uses neutral text; the green item dot denotes equipped gear. EquipmentInventoryUI holds serialized templates and responsive grid sizing; EquipmentPageUI remains the action/data presenter.

The existing text object/font and real CombatStats.Power binding are preserved; the visible Total Power label is replaced by the icon.

It does not capture raycasts or keyboard selection. Empty slots show no tooltip. Exit, pointer press/drag, Escape, source disable, inventory refresh, page closure and application focus loss dismiss the preview. Clicking still opens the centred actionable modal with its normal backdrop, keyboard focus, equip/unequip and upgrade controls. Hover never changes the selected action item or save data.

### Shared character equipment circles

`Assets/Prefabs/CatCharacter.prefab` is the project-owned Ninja character variant for new character previews. Its nested `Assets/Prefabs/CharacterEquipmentAura.prefab` owns the shared circle references, body anchor, scale and three-piece lift. Existing scene actors and the Focus training actor reuse that same nested presentation prefab while retaining their original objects, controllers and animation paths. Edit the shared aura prefab to update every connected location; do not edit the vendor Ninja or VFX originals.

Only valid, owned and equipped pieces count (EquipmentRules.Calculate). Show the colour with the most pieces, breaking ties toward the higher tier. No equipped pieces means no circle. Blue uses Circle_Effect_7 / 13 / 19 for one / two / three pieces; purple uses 9 / 15 / 21; yellow uses 10 / 16 / 22. These circular effects sit behind the character body; the former Magic_Circle ground effects are no longer instantiated. The vendor Demo_Item_Icon_3 child is hidden only on runtime instances. The effect is presentation only and never modifies set bonuses, rewards or saves. Refresh follows the committed TaskService.Changed event, with cleanup on page disable and reconstruction on reopen.

Dashboard, Cat Home, Focus, the three Boss stage prefabs and existing Ninja scene actors share the aura. The Companion receives only the selected tier and piece count from the authoritative main process; it does not open the player's save. Disconnection hides the circle until a valid host state returns.

Opt-in regression: `Temp/verify-character-aura.request`. Current-run reports and captures are written under `Library/CharacterAuraVerification/<UTC timestamp>/`; tests use disposable saves. The checker does not generate or repair authored assets.

Aura occlusion: the runtime presenter groups the cat and its circle for environment sorting, then draws the particles behind the cat inside the group. Unequipping disables its owned group to restore original sorting. Shared circle scale is 3.5 and characterOffset is (-0.9, -0.55, 0); three-piece lift is 0. The renamed characterOffset field migrates the former footOffset using FormerlySerializedAs. Vendor start speed is overridden to zero so depth travel cannot produce drift in the Boss perspective camera; texture animation remains.

Mastery rewards use the existing EquipmentClaimUI with one row of chests (no lower choice row). Blue/purple/yellow backgrounds identify Cyclope/Orc/Demon quality. Each chest previews its fixed item; a committed claim reveals the item and Owned status. Hover, including locked and collected rewards, reuses the non-blocking EquipmentItemDetail preview with actual stats. Service-level win gates and existing atomic claim settlement prevent early or duplicate rewards. Legacy out-of-order owned equipment is retained and remaining pieces can still be collected. Temp/verify-chest-reward.request runs isolated UI/hover/claim checks; EquipmentVerification includes fixed milestone boundaries, failure/retry and legacy completion.
